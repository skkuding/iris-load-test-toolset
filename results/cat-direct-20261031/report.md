# 2026-10-31 Judger CAT 균등 할당 예비 A/B 테스트

## 결론

`codedang8`에서 컨테이너를 제외하고 호스트의 `judger-bench → libjudger.so` 경로를 직접 실행했다. 같은 배치의 대조군과 CAT 균등 할당군을 8·16·30개 작업에서 비교했다. **이 연산 중심 fixture에서는 CAT로 채점 CPU 시간이 개선되지 않았다.** 중앙값은 각각 434→437ms(+0.69%), 497→498ms(+0.20%), 570→571ms(+0.18%)였다. 이 결과는 단계마다 A/B 한 쌍의 예비 측정이며, 캐시 의존적인 다른 문제까지 일반화할 수 없다.

## 실험 조건

- 서버: `codedang8`, LLC 도메인 2개, 각 20-way(`cbm_mask=fffff`), CAT CLOSID 16개. 최상위 2-way(`shareable_bits=c0000`)를 제외한 18-way를 사용했다.
- 각 단계에서 작업의 절반을 각 LLC/NUMA 도메인에 배치했다. 대조군과 CAT군은 동일한 논리 CPU 고정, `numactl --membind` 로컬 메모리, 입력·출력·실행 바이너리·libjudger를 사용했다. 30개 단계는 SMT 형제 스레드도 사용한다.
- 작업별 50회 반복. 총 5,400회 모두 `success`이며 기대 출력 해시가 일치했다. 통계는 모든 작업의 실행 구간 교집합에 완전히 포함된 샘플만 사용했다.
- CAT군은 각 LLC 도메인의 `n/2`개 작업에 비중첩 CBM을 각각 할당했다. 8개에서는 작업당 4-way, 16개에서는 2-way, 30개에서는 1-way다. resctrl 그룹의 실행 중 task 수와 schemata를 확인했다.
- CMT/MBM은 1초 간격으로 측정했다. MBM 값은 메모리 컨트롤러 트래픽이며 LLC 트래픽이 아니다.

## 해석과 다음 실험

CAT는 캐시에 들어오는 데이터의 위치를 제한했지만, 이 fixture의 CPU 시간은 세 단계 모두 사실상 그대로였다. 기존 4차 테스트 문서의 `cpp-runtime-v1`은 ALU/레지스터 중심이고 메모리 44MiB를 시작 시 한 번 터치하므로, CAT의 캐시 간섭 완화 이득이 작을 수 있다. 캐시 의존적 문제(`chase6` 등)와 서로 다른 작업을 섞은 부하에서 A/B를 반복하고 `cycles`, `instructions`, LLC miss를 함께 측정해야 운영 정책의 이득을 판단할 수 있다.

이번 실행은 호스트 직접 실행의 `production-compat` 모드다. stock libjudger가 호스트 cgroup 루트에 sandbox를 생성하므로 도구의 컨테이너 격리용 `cgroupContained`와 `comparable` 필드는 false다. 각 샘플의 실제 sandbox 경로와 성공 상태는 별도로 검증했다. 이전 컨테이너 사다리 측정과 절대값을 합쳐 비교하지 않는다.

재현 스크립트와 분석 방법은 `docs/CAT-DIRECT-AB.md`, `scripts/run-direct-cat-ab.sh`, `scripts/analyze-direct-cat.py`, `scripts/plot-direct-cat.py`에 정리했다. 아래 도표는 동일한 원시 NDJSON·RDT TSV에서 생성했다.
