# 3차 (2026-10-21): Go 1.25.14 → 1.27.3 교체 회귀 확인

원문: [3차 결과](https://app.notion.com/p/400ef9cff54581a19091d4e9b923770b).

## 질문

eMudhra 중간 CA 키 유출(CVE-2026-111943) 대응으로 Iris 빌드 도구를 Go
1.25.14에서 1.27.3으로 올렸습니다. 이 교체가 채점 실행 시간이나 재현성을
바꾸는가? 보안 패치 자체의 검증은 별도로 기록했습니다.

## 조건

- 경로: [2차](2026-09-27-full-iris.md)와 같은 Full Iris 외부 데이터 경로.
  같은 RabbitMQ, Judger alpha.4, RDS `v1`, S3 object set, 문제 568/15850.
- 비교 이미지: 같은 `apps/iris` 소스와 같은 `ca-certificates`
  (`20260816ubuntu0.24.04.1`)로 두 이미지를 만들었습니다.

| 이미지 | Go | digest |
| --- | --- | --- |
| `codedang-iris:go125` | 1.25.14 | `sha256:44d92e81c70317aaec7088525435b70955e64c2ac2422a8e2c624f2aa1e7abf9` |
| `codedang-iris:go1.27.3` | 1.27.3 | `sha256:383c4da386aef61582028f1d360792477f7e7626625cfaef8fd3fa3a1cff0c55` |

- 측정: 4 replica에서 이미지당 2회(이미지당 400 표본). 보조로 운영 계열
  baseline(`98adb52a…`)과 새 이미지를 1·4·8 replica에서 비교했습니다.
- 각 run 사이 load1 < 0.8을 기다렸습니다. load1 > 1.0이면 자격 검사에서
  run이 거부되므로 성공한 run만 집계했습니다.

## 결과 (4 replica, 이미지당 400 표본, ms)

| 지표 | Go 1.25.14 | Go 1.27.3 | 차이 |
| --- | ---: | ---: | ---: |
| CPU 중앙값 | 400.0 | 398.0 | −0.5% |
| CPU p95 | 426.1 | 434.1 | +1.9% |
| CPU p99 | 442.0 | 442.0 | 0.0% |
| real 중앙값 | 437.0 | 434.0 | −0.7% |
| real p95 | 466.1 | 473.0 | +1.5% |
| E2E p95 | 50,887 | 50,773 | −0.2% |
| Judger 메모리 중앙값 (MiB) | 44.75 | 44.75 | 0 |

- 같은 이미지를 두 번 돌렸을 때 CPU p95 범위가 약 2.3%였습니다. p95 차이는
  회차 간 변동 안에 있습니다.
- production baseline과의 비교에서도 1·4·8 replica 모두 ±1% 안이었습니다.
- Iris 프로세스 RSS는 늘지 않았고 OOM이나 재시작은 없었습니다. `x509`
  오류나 S3 데이터 소스 오류도 없었습니다.

## 결론

Go 1.27.3 전환으로 인한 성능 회귀는 관측되지 않았습니다. 3차는 새 동시성
사다리가 아니라 2차 기준선 위에서 이미지만 바꾼 확인 실험입니다.

## 재현

[2차 재현 명령](2026-09-27-full-iris.md#재현)에서 `--iris-digest`만 비교할
이미지로 바꿉니다. 두 이미지는 브랜치에서 직접 만든 로컬 이미지이므로, 같은
digest를 쓰려면 같은 소스와 Dockerfile로 다시 빌드하거나 당시 이미지를 받아야
합니다. 다음 순서로 실행합니다.

1. 각 이미지를 4 replica(`external-4`)에서 A/B를 번갈아 두 번씩 실행합니다.
2. 보조 비교가 필요하면 `external-1`, `external-8`도 실행합니다.
3. `bin/iris-benchctl analyze --run runs/<run-id>`로 각 run을 요약합니다.
4. RSS가 필요하면 run 중에 `docker stats`를 2초 간격으로 따로 수집합니다.
   이 기능은 도구에 들어 있지 않습니다.

## 산출물

- A/B: `runs/iris-20261021-go125-4-{a,b}`, `runs/iris-20261021-new4-{a2,b2}`
- 추세 비교: `runs/iris-20261021-{old,new}1-a`, `runs/iris-20261021-old4-{a,b}`,
  `runs/iris-20261021-{old,new}8-{a,b}`

## 한계와 제안된 다음 단계

- A/B는 4 replica 2회뿐입니다. 16/30 replica와 재부팅 반복은 하지 않았습니다.
- CI/CD가 만든 최종 이미지로 stage에서 전체 사다리를 다시 측정하자는 제안이
  있었습니다.
