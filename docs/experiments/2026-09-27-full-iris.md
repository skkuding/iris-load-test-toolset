## 질문

1차에서 걷어낸 Iris 서비스 경계를 다시 넣어도 같은 결과가 나오는가? 운영
RabbitMQ·DB·Kubernetes는 건드리지 않습니다.

## 경로

```text
벤치마크 publisher
  → 실행 전용 RabbitMQ /loadtest
  → 운영 Iris 컨테이너
  → 벤치마크 RDS 읽기 전용 preflight
  → codedang-iris-benchmark-testcases S3
  → Judger alpha.4
  → 실행 전용 RabbitMQ 결과 큐
  → collector와 검증 번들
```

client-api HTTP 제출, Redis, DB 결과 갱신은 포함하지 않습니다.

## 부하 시작 순서

처리량이 대상 성능에 좌우되지 않도록 큐를 먼저 채웁니다.

1. RabbitMQ 시작, 토폴로지 선언, 큐 purge
2. 결과 collector 연결
3. 전체 요청을 `mandatory=true`와 publisher confirm으로 발행
4. 요청 큐 깊이가 계획한 수와 같은지 확인
5. 모든 Iris 컨테이너를 공통 barrier 뒤에서 한 번에 시작
6. 요청마다 테스트케이스 결과 1개와 최종 결과 1개 수집

통과 조건은 발행 수 = 확인 수 = 계획 수, 중복·재전달·누락·예상 밖 ID 0,
종료 후 두 큐 0, 모든 결과 `resultCode=0`, 잔여 컨테이너·네트워크·
`/sandbox-*` cgroup 0입니다.

## 결론

- 모든 run에서 메시지가 보존되었습니다.
- Full Iris 값은 1차 직접 Judger 값과 거의 같습니다(30 replica CPU 553 vs
  564ms). 파일럿의 30대 771ms, CV 35%는 Kubernetes·운영 Iris 20개·네트워크가
  같은 노드에 있었던 영향으로 봅니다.
- 처리량은 30 replica까지 거의 선형으로 늘지만, 16→30 구간은 물리 코어
  한계로 증가율이 둔화됩니다.
- 첫 30 replica 시도는 워커별 cgroup 정리 helper가 30초 예산을 넘겨 잔여
  cgroup을 남겼습니다. helper 하나로 일괄 제거하고 5분 정리 예산을 따로 두도록
  고친 뒤 `iris-20260927-ladder-30x-r2`로 다시 실행했습니다.

## 재현

공통 준비는 [재현 가이드](../REPRODUCTION.md)를 따르세요. 아래는 재부팅 1회와
사다리 1회를 수행하는 회차 스크립트입니다. `R`은 회차 번호입니다.

```bash
#!/usr/bin/env bash
set -euo pipefail
cd <repository-root>
R="$1"
SOCK="$HOME/.ssh/sockets/codedang8.sock"
IRIS=sha256:98adb52a1f41837def5e7d725b9052e04a8b7b48ed1bcdcaa1d66f0ff5fe41e7
RABBIT=sha256:606d8c0d6b3c18d1da9afc53bc7cdb2a8d5486df91b5a9830e9e07626c9ae281
JUDGER=2c9a4da817e06f49daabe6b437f81d10f78b42be517d2e345ab4f868a4189103
OBJ=sha256:5fa11ffb80db063b982cc142d110c7c0fdd46b1abf299cca77a0276dc0cad615

ssh_plain() { ssh -o BatchMode=yes -o ControlMaster=no -o ConnectTimeout=8 codedang8 "$@"; }
ssh_sock()  { ssh -S "$SOCK" -o BatchMode=yes codedang8 "$@"; }
wait_load() {
  for _ in $(seq 1 90); do
    load="$(ssh_sock 'cut -d" " -f1 /proc/loadavg')"
    awk -v l="$load" 'BEGIN{exit !(l<0.7)}' && return 0
    sleep 10
  done
  return 1
}

# 재부팅 후 SSH와 control master를 다시 연다 (server8 sudoers는 reboot만 무암호 허용)
ssh_plain 'sudo -n /usr/sbin/reboot' >/dev/null 2>&1 || true
sleep 15
for _ in $(seq 1 90); do ssh_plain true >/dev/null 2>&1 && break; sleep 5; done
rm -f "$SOCK"
ssh -M -S "$SOCK" -o ControlPersist=3600 -o BatchMode=yes -fN codedang8
until [ "$(ssh_sock 'systemctl is-active docker')" = active ]; do sleep 10; done

set -a; source .env.example; set +a
for N in 1 2 4 8 16 30; do
  wait_load
  scripts/aws/build-iris-runtime-env.sh --out /tmp/iris-runtime.env \
    --secret-profile codedang-iris-benchmark-terraform \
    --s3-profile codedang-iris-benchmark-read --yes >/dev/null
  RUN="iris-<YYYYMMDD>-r${R}-${N}x"
  bin/iris-benchctl run \
    --config config/full-iris-external.json --host codedang8 --profile "external-${N}" \
    --iris-digest "$IRIS" --rabbitmq-digest "$RABBIT" --judger-digest "$JUDGER" \
    --iris-source fixtures/iris-external-568/source.cpp --iris-env-file /tmp/iris-runtime.env \
    --problem-id 568 --language Cpp --time-limit-ms 1000 --memory-limit-bytes 1073741824 \
    --testcases-per-request 1 --message-id-start $(( 3000000 + R*1000000 + N*1000 )) \
    --rds-generation v1 --s3-object-set "$OBJ" --s3-bucket codedang-iris-benchmark-testcases \
    --production-compat --local-agent bin/iris-bench-agent \
    --ssh-control-path "$SOCK" --run-id "$RUN"
  bin/iris-benchctl collect --config config/full-iris-external.json --host codedang8 \
    --run "$RUN" --ssh-control-path "$SOCK"
done
rm -f /tmp/iris-runtime.env
```

  `codedang-iris-benchmark` 밖의 Secret, 호스트, 역할, 버킷을 거부합니다.
- 재부팅은 호스트에 영향을 주는 작업입니다. 실행 전에 사용자 승인을 받으세요.
